CrabCache

以 Cloudflare Pingora 为网络与代理核心构建的 Rust API 网关；在 Pingora ProxyHttp 过滤器链上扩展 DeepSeek V4 / Cursor 能力。

Rust 2024 Pingora 0.8 ProxyHttp MIT License DeepSeek V4

为什么以 Pingora 为核心

Cloudflare 开源、生产验证的 Rust 代理框架 — CrabCache 的全部流量经 Pingora 处理

Pingora
ProxyHttp 生命周期 · 无锁连接池
SSE
流式 body_filter · 逐 chunk 改写
Rust
零拷贝 Bytes · jemalloc
DeepSeek
业务层：路由 · Reasoning · 控制面

缓存分层说明

L0–L2 与 L3 是两套独立指标，请勿混谈「命中率」

L3 DeepSeek 服务端前缀缓存
计费 Token 折扣 依赖 稳定 messages 前缀 + 粘滞路由
L0 Moka 内存 · 精确响应缓存
延迟 < 100μs 级 需 body 完全一致
L1 Redis · 跨实例共享
延迟 < 5ms 同上，精确键
L2 Qdrant 语义缓存（可选）
相似度阈值可配 对聊天场景收益有限

请求处理架构

从客户端请求到上游 DeepSeek 的完整处理管线

客户端请求
↓
认证 & 缓存键生成
→
L0 / L1 / L2（可选，多数未命中）
↓ 网关 L0–L2 通常未命中
Request Coalescing
→
Ketama → DeepSeek（L3 前缀）
↓
SSE 流式处理
→
Reasoning 恢复
→
写入 L0+L1+L2
→
返回客户端

快速开始

3 分钟启动 CrabCache 网关

# 1. 克隆仓库 git clone https://github.com/smile9493/CrabCache.git cd CrabCache # 2. 构建网关 cargo build --release -p crab-gateway # 3. 复制并编辑配置文件 cp config/gateway.example.toml config/gateway.toml # 4. 启动 Redis（L1 缓存必需） docker compose up -d redis # 5. 启动网关 cargo run --release -p crab-gateway -- config/gateway.toml
